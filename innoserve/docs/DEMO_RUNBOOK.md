- **D6**：0:00 請評審從首頁 4 份示範合約挑一份按下，放在背景跑，問答時揭曉；沒證實就照實顯示。
- **2:30～3:20 用方案 e**（D21）：`live_attack_stakingvault.py`。畫面和旁白都要有「**這段鏈上攻擊是事先寫好的參考攻擊（victim_probe 的 DRAIN），不是 AI 這次產生的**」。WithdrawalQueue（`live_attack.py`）是第二備案 3b。
- **0:00 的快取用哪一份還沒決定**（P9 報告「0:00 快取的候選」，由使用者決定）。腳本預設是候選 (a)：spark-test-2 的錄製回放（10/28）。改用候選 (b) P8 主設定第 3、6 次：加 `--cache-result 76f5896b7db0`（第 3 次）或 `--cache-result 81c3a7a659ea`（第 6 次）。

## 開場前 15 分鐘：第 0 段（不算在 6 分鐘裡）

`scripts/demo_gate.sh --live` 的第 0 段依序做：

1. **preflight（12.7 的清單，逐一看結束碼）**：forge／anvil／cast 版本、`api_smoke`、8 個 probe（victim、forgery、halt、drain、sweep、latebinding、setup_forgery、gain）、`patch_probe`、`live_attack`（8599）、`live_attack --patched`（8600）。
   **全部 rc 0 才開場**；任何一條不是 0，腳本印 `PREFLIGHT FAILED: 不開場，改走 L1` 並停下來（rc 1）。
2. 網頁：在跑就沿用，沒在跑就啟動（127.0.0.1:8765）。
3. 檢查本地鏈要用的埠 8600、8601、8610、8611 沒被占用。
4. **方案 e 暖機一次**：冷啟動時 forge／anvil／cast 第一次很慢（10/31 實測原合約一次 70 秒），先跑一次。暖機失敗時腳本自動把第 3 段換成備案 3b。
5. **先把錄製紀錄放完**：spark-test-2 的錄製回放（4 倍速）在這時跑完，6 分鐘裡只開它的工作頁和結果頁。
   原因：網頁一次只跑一個工作，現場上傳會占住 2～8 分鐘；回放如果排在它後面，就要等。
6. 印出 4 個分頁的網址，照著開好：
   - 分頁 1 上傳頁 `http://127.0.0.1:8765/`
   - 分頁 2 錄製紀錄的工作頁 `…/job/<id>?stay=1`（逐回合；`?stay=1` 不會自動跳走）
   - 分頁 3 結果頁 `…/result/<12 碼>`
   - 分頁 4 `…/github`（PR 的本機截圖，不用網路）；有網路再另開 GitHub PR #1
- 第 0 段實測 207～485 秒（10/31，2 次；這台筆電晚上效能起伏很大，同一個 probe 會從 2 秒變成 13～40 秒）→ **至少提前 15 分鐘開始**。

## 個別狀況

1. **DGX 連不上**：preflight 的 api_smoke 失敗 → 照 12.7 不開場、改走 L1。說：「模型主機現在連不上，現場上傳跳過；錄製紀錄和真鏈都不需要模型。」
2. **現場上傳沒證實**（未發現可證明攻擊、靜態工具提示但未證實、或無法判定）：照實說明，見問答那一列。
3. **anvil 起不來**：第 3 段只講結果頁的 A/B/G。說：「鏈上的結果在報告裡：原合約 2/0/7，修補後 2/2/0，連跑 3 次交易 hash 都一樣。」
3b. **方案 e 在這台跑不起來，但 anvil 可以用**（第二備案，D21）：第 0 段暖機失敗時腳本會自動換成下面這組，並在畫面印出換了合約。手動跑：
   ```bash
   cd ~/innoserve/arbiter-audit/arbiter
   echo '【換了合約：WithdrawalQueue（不是 StakingVault）。這段鏈上攻擊是事先寫好的參考攻擊，不是 AI 這次產生的】'
   python3 scripts/live_attack.py && python3 scripts/live_attack.py --patched
   ```
   說：「這裡換成另一個合約 WithdrawalQueue，攻擊一樣是事先寫好的參考攻擊，不是 AI 這次產生的。」
   10/30 實測：原合約 PROVEN（佇列被提走 6 ETH、攻擊者淨得 5.9999 ETH、受害者短少 5 ETH），`--patched` NOT PROVEN。
4. **瀏覽器或網頁打不開**：終端機每一段都印出同一份結果的內容，直接念。
5. **誤點首頁其他按鈕**（回放、真鏈示範）：現場上傳在跑時會排在後面等好幾分鐘。回到已經開好的分頁就好；工作頁重新整理不會重跑。
6. **鏈上兩向到 3:20 還沒跑完**：切回分頁 3，口頭講備案 3 那句；跑完後終端機會自己印出來。

## 不要說、不要做

- 不要說「安全」「CLEAR」「首創」（「不等於安全」這種否定句可以）。
- 不要把鏈上攻擊說成 AI 寫的；不要把錄製紀錄說成現在這一次。
- 不要說修補「修好了合約」：修補只「針對此攻擊」通過驗證；P7b 有通過檢查但多了一行不必要修改的實例（D17）。
- 數字一律「N 次中 M 次」並標模型；不要把 arbiter-gpt 和 nemotron 的數字放在一起比。
- 被問到寬鬆謂詞：tools.py 的 run_exploit 說明只列舊謂詞（CLAUDE.md 第 7 節已知陷阱 13），決賽前不修；寬鬆謂詞證實的結果畫面照實標示，A/B/G 與修補只對 victim_loss／liveness_broken 提供。
- **不准合併 demo repo 的 PR #1**（決賽紅轉綠），也不要推 commit 或重跑它。
