# ARBITER Gate 決賽 demo runbook（11/7）

```bash
cd ~/innoserve/arbiter-audit/arbiter
scripts/demo_gate.sh --live      # 每段按 Enter 繼續；DGX 連不上就拿掉 --live
```
數字一律是 **arbiter-gpt:latest**（10/28 量的），不要和 AIS3 時期 nemotron 的數字混用。

## 開場前檢查清單（上台前 30 分鐘）

- [ ] **SSH 通道**：`ssh -f -N -L 8080:localhost:8080 -L 11434:localhost:11434 <user>@<DGX 位址>`，再用 `ss -ltn | grep 11434` 確認有在聽。
- [ ] **.env**：`arbiter-audit/.env` 要有 `AIS3_API_KEY=local`、`AIS3_BASE_URL=http://localhost:11434/v1`、`AIS3_MODEL=arbiter-gpt:latest`。腳本會自己 source，不用先 source。
- [ ] **模型預熱**：上台前 5 分鐘內跑一次 `python3 scripts/api_smoke.py`，要看到 PASS。第 1 次排練時第 0 段花了 15 秒，之後只要 2～4 秒；推測是 Ollama 閒置後要重新載入模型，沒有查證。
- [ ] **web**：用 `curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8765/` 確認回 200。沒在跑的話腳本第 0 段會自己啟動，log 在 `runs/gate/demo/web.server.log`。
- [ ] **anvil**：`anvil --version`，並確認 8600、8601、8610、8611 這幾個埠沒被占用。
- [ ] **瀏覽器先開兩個分頁**：
  - 分頁 1：首頁 http://127.0.0.1:8765/，第 1 段要在這裡上傳。
  - 分頁 2：spark-test-2 結果頁。排練時第 0 段印出的 `/result/<12 碼>` 網址重開伺服器後仍然有效，可以先開好。
- [ ] **上台前不要跑其他 gate 或上傳**：網頁一次只跑一個工作。
- [ ] 終端機字放大，視窗寬度至少 140 欄；交易 hash 一行很長。

## 流程

| 段 | 實測（不含講話） | 要點一句話 | 要主動說的話 |
|---|---|---|---|
| 0 前置 | 3.5～15 秒 | 通道、工具、網頁都好了，預錄結果頁已經產生 | （不用講，開場前先跑完也可以） |
| 1 即時上傳（`--live`） | 0.1 秒＋**背景 2～8 分鐘** | 現場把 StakingVault.sol 丟給模型，先放著。**建議在報告開場就送出，不要等到 demo 段** | 「這次是真的呼叫模型，大約 2 到 8 分鐘，最後再回來看。」 |
| 2 預錄 | 0 秒（看頁面） | 已證實可攻擊；A/B/G 四個環境；模型修補通過五道檢查 | 「A 是沒有攻擊時受害者拿回多少，B 是有攻擊時拿回多少，G 是攻擊者賺多少。」「模型的攻擊只在 8 輪環境讓受害者受損，我們照實顯示。」「修補只說『針對此攻擊』通過驗證。」 |
| 3 真鏈 | 13.5 秒 | 原合約金庫 7→0，PROVEN；套 AI 修補後 attack() revert，NOT PROVEN | **「鏈上的攻擊是已知的參考攻擊（victim_probe 的 DRAIN），不是模型寫的；修補是 AI 產生的。」** |
| 4 收尾 | 0 秒 | 回分頁 1 看即時結果 | 「未發現可證明攻擊**不等於安全**，只代表這次模型沒寫出能在 EVM 上成立的攻擊。」 |

- **要拉長講的地方**：腳本走到第 4 段時，即時稽核才跑了大約 30 秒，實測卻要 125～465 秒。所以第 2、3 段要講到分頁 1 自己跳轉之後，才進第 4 段。也可以按 Enter 前先看分頁 1 有沒有跳轉。
- 排練時即時上傳那次花了 247 秒，判「未發現可證明攻擊」（agent_concluded_no_attack）。所以備案 2 很可能真的會用到。

## 備案

1. **DGX Spark 連不上**：第 0 段 api_smoke 大約 2 秒就會失敗，腳本會自動跳過第 1 段，不會上傳。
   要說：「模型主機現在連不上，即時稽核跳過；預錄和真鏈都不需要模型。」
2. **即時上傳沒有證實**（未發現可證明攻擊，或無法判定）：照實說明。
   要說：「這次沒有證實。arbiter-gpt 在 repo 模式累計用 victim_loss 證實 9/15（10/28），大約三次有一次不成功，所以主線用預錄。」然後切回分頁 2。
3. **anvil 起不來**：腳本會跳過第 3 段，只看網頁預錄的 A/B/G。
   要說：「鏈上的結果在報告裡：原合約 2/0/7，修補後 2/2/0，連跑 3 次的交易 hash 都一樣。」
4. **瀏覽器或網頁打不開**：第 2 段終端機會印出同一份 gate.json 的判定、A/B/G 和修補檢查，直接念。
5. **誤點首頁其他「看結果」**：如果即時稽核還在跑，那個點擊會排在後面，等好幾分鐘。開新分頁回 spark-test-2 的網址就好，不要重新整理分頁 1。

## 不要說、不要做

- 不要說「安全」「CLEAR」。
- 不要把鏈上攻擊說成模型寫的。
- 不要說修補「修好了合約」。交叉驗證只涵蓋 2 種手法，而且都是 unstake() 重入。
- 被問到寬鬆謂詞時，見 CLAUDE.md 第 7 節已知陷阱 13：tools.py 的說明只列舊謂詞，決賽前不修。
