## 5. 背景程式會不會在關掉終端機後被停掉（4e）

查到的事實：

- `/etc/wsl.conf`：`[boot] systemd=true`、`[user] default=<user>`。PID 1 是 systemd，`systemctl is-system-running` 回 `running`。
- logind 是預設值（`KillUserProcesses=no`），`Linger=no`。
- 程序樹：每個 Windows 端打開的終端機，都是 `/init` 下的一個 `SessionLead → Relay → bash`。
  - Claude Code（`claude`）在其中一個 session 裡。
  - **DGX 的 SSH 通道（`ssh -f -N -L 8080… -L 11434…`）掛在同一個 Relay 底下**。它是從 Claude Code 所在的終端機啟動的。
  - Docker Desktop 也自己開了一個 session（`docker-desktop-user-distro proxy`）。
- 沒有 `.wslconfig`，所以 WSL 用預設的閒置關機行為：所有 Windows 端的 WSL 連線都關掉後，過一段時間 WSL 會整個停掉。systemd 底下的背景程式不會讓 WSL 保持開著。

結論（今晚要跑一整晚評測）：

1. **保持一個 Ubuntu 終端機視窗開著**。建議專門開一個視窗跑 `tmux`，把評測和 SSH 通道都放進同一個 tmux session。不要把通道留在會被關掉的分頁裡。
2. **Windows 不能睡眠或休眠**：接上電源，電源計畫的「睡眠」設成「永不」，闔上螢幕時設成「不執行任何動作」。電腦一睡，WSL VM 和 SSH 通道都會停。
3. 不要執行 `wsl --shutdown`，也不要重開機或讓 Windows Update 自動重開機。
4. Docker Desktop 也會在 Ubuntu 裡開一個 session，可能讓 WSL 一直開著。但這是推測，沒有測過，所以不要靠它。
5. 中斷了也沒關係：用同一個 run-id 重跑就會接著做（`run.py` 會跳過已完成的列）。早上要檢查 `usage.models_seen` 只有一個值，而且沒有任何一列的 error 以 `ModelMismatch` 開頭。
