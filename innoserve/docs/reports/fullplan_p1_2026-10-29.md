## 1. dump.py（小改）

- `PREDICATE_NOTES` 補上 `victim_loss`：有攻擊時受害者取回的比沒有攻擊時少，而且攻擊者至少多了這個差額。
- README 範本原本寫「攻擊者拿到的比一般使用者多」（舊的 eth_profit 判準），改成照這次證實用的謂詞寫判定條件。
- `_vendor`：原本會把 remapping 的絕對路徑去掉開頭的 `/` 後放進 `sources/`，所以每份 dump 都有 `sources/home/<user>/…`。
  現在改成相對於 repo 根目錄；repo 外的目錄用中性名稱 `sources/external/<n>_<名稱>`。
  驗證：spark-test-2 的 dump 現在是 `arbiter-target/=sources/`，專案內 0 個 `/home/`。
- **已知問題（不是這次造成、這次不修）**：`dump_run` 的 `reproduces` 是 0。用 P1 之前的程式碼（eval worktree）跑同一份輸入，結果也是 0。
  原因是 dump 的 foundry.toml 強制 `via_ir = true` 但 `optimizer = false`，StakingVault 的攻擊檔編譯時出現「Stack too deep」。
  這影響 `cli.py dump` 和 `prove`，不影響這次的回歸測試（回歸測試用 `via_ir = false`，實跑通過）。建議排進 P6 或 P9。

## 2. TestArbiterRegression（計劃書 6.6）

- 寫法：附加在已存的攻擊檔後面，和 TestArbiterReport 同一個做法。
  - `testExploitBlocked()`：`vm.expectRevert(); this.arbiterRun();`，攻擊在 4 種環境都必須失敗。
  - `testHonestPath0..3()`：直接呼叫 `arbTrial(false, …)`，要求 取回金額 ＋ 10 wei ≥ 原合約的 A。
    A 用 gate.json 裡已量好的值（patch.reproduce 的報告合約），所以產生下載檔不需要再跑 forge。
- **和計劃書不同**：計劃書要 README 教使用者用 `--match-contract`／`--match-test` 避開繼承來的 `testArbiterVictimLoss`（修補後一定會失敗）。
  我改成在交付的檔案裡把它改名為 `arbiterVictimLossProof()`，函式還在，只是不會被當成測試執行。
  這樣放進專案後直接 `forge test` 就只跑那 5 個測試，不會出現一個「正常的失敗」嚇到使用者。README 仍有寫 `--match-contract TestArbiterRegression`，給已經有其他測試的專案用。
- 只有 `victim_loss` 而且 A/B/G 有量到的結果才產生回歸測試。其他情況用一句白話說明原因，例如寬鬆謂詞：

- 專案內容：`README.md`（白話：用途、每個測試檢查什麼、怎麼跑、怎麼放進自己的專案、限制、來源模型）、`foundry.toml`、`src/<原檔名>.sol`、`test/arbiter/ArbiterRegression.t.sol`、`test/arbiter/Vm.sol`（不需要 forge-std）。

## 3. sarif.py（計劃書 7.4）

| 判定 | SARIF |
|---|---|
| 已證實可攻擊 | 每個 finding 一筆 result，`level: error`，`ruleId` = `arbiter/proven/<vuln_class>`，位置是漏洞函式的定義（第一行到結尾大括號）。`security-severity` 依 High／Medium… 對應，`partialFingerprints` 用 uri＋函式＋類別 |
| 靜態工具提示但未證實 | `level: warning`，`ruleId` = `slither/<check>`。對應已寫好，讀 `static_hints`，P2 才會有資料 |
| 未發現可證明攻擊 | 不產生 result，只列在 `run.properties.coverage`。另附「沒有 alert 不代表合約沒有漏洞」 |
| 無法判定 | 不產生 result；`invocations[0].executionSuccessful=false`，原因寫在 `toolExecutionNotifications` |

- 路徑：`uriBaseId: %SRCROOT%`＋相對 uri（spark-test：`StakingVault.sol`；上傳：檔名）。
- 行號：gate.py 的 `locate_function()`。先找函式定義，找不到才用 offending_expression（空白正規化），每個 finding 都記下用的是哪一種。
  spark-test-2：`unstake()` 第 20～30 行，basis＝function_definition，已對照原始碼。
- Schema：`arbiter/tests/data/sarif-schema-2.1.0.json`。來源是 OASIS SARIF 2.1.0 Errata 01：
  https://docs.oasis-open.org/sarif/sarif/v2.1.0/errata01/os/schemas/sarif-schema-2.1.0.json ，sha256 c3b4bb2d…682e，記在同資料夾的 README。
- 驗證工具 `scripts/sarif_validate.py`：用 jsonschema 4.26.0（裝在 `~/innoserve/venv-tools`，不進 arbiter 套件，arbiter 仍只用標準函式庫），Draft-04 validator。

## 5. 網頁下載區

- 每個下載鈕旁邊都有一句白話：
  - 修補檔：通過修補閘門的修改。可以在回歸測試資料夾裡用 `patch -p1` 套用；放進你的專案前請先審閱。
  - 回歸測試：把這份測試放進你的專案，以後每次修改都會自動再試一次同樣的攻擊，並確認沒有攻擊時一般使用者拿回的錢沒有變少。
  - gate.json：完整的機器可讀結果，給 CI 或其他工具讀。
  - report.sarif：上傳到 GitHub 的 Code scanning；已證實的漏洞會以 error 標在對應的程式行。
- 不能下載的項目，按鈕變灰，下面寫原因。
- `.patch` 的檔頭改成 `src/<原檔名>.sol`，和回歸測試專案的結構一致，所以在專案裡 `patch -p1` 可以直接套用（已實測）。
- 回歸測試 zip 是點下去時才產生：讀結果檔，加上 gate.json 裡的 A，不跑 forge。所以 P1 之前存的結果頁也能下載。
- 「尚未完成的部分」清單只改一處：拿掉「SARIF」「回歸測試下載」兩項（已完成，留著會和事實不符），「GitHub Action」保留為開發中。版面其他地方沒動。
